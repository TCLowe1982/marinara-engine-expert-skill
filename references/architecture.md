# Marinara Engine: Architecture Overview

Marinara Engine is a local-first AI roleplay and chat frontend. Users run it on their own machine (Windows installer, Docker, Node.js clone, or Termux on Android), plug in their own AI API keys (OpenAI, Anthropic, Google, xAI, OpenRouter, Mistral, Cohere, or any OpenAI-compatible endpoint), and chat with AI characters.

Repo: https://github.com/Pasta-Devs/Marinara-Engine
Built by SpicyMarinara & Pasta-Devs. License: AGPL-3.0.

## The Big Picture

```
┌─────────────────────────────────────────────────────────────┐
│  Client (React / Tailwind v4, PWA-capable)                  │
│  - Chat UI  - Agents panel  - Lorebook editor               │
└──────────────────────────────┬──────────────────────────────┘
                               │ fetch /api/*
┌──────────────────────────────┴──────────────────────────────┐
│  Server (Fastify, TypeScript, file-native JSON store)       │
│  Routes: characters, lorebooks, agents, custom-tools,       │
│          generate, chats, presets, connections, etc.        │
│  ↓                                                          │
│  Generation pipeline (packages/server/src/routes/generate*) │
│   ├─ Assemble system prompt from: card + scenario +         │
│   │   connected chats + awareness + lorebook injection      │
│   ├─ Run pre-generation agents (inject, review, rewrite)    │
│   ├─ Stream response from the configured LLM provider       │
│   │    (with tool-calling if tools are enabled)             │
│   ├─ Run parallel agents (images, music, echo reactions)    │
│   └─ Run post-processing agents (state extraction, editor)  │
│  ↓                                                          │
│  File store: messages, chats, characters, personas,         │
│  lorebooks, presets, agents, custom-tools, etc.             │
└─────────────────────────────────────────────────────────────┘
```

**Package split (v2.3)** — the base Engine no longer ships optional agents. Hierarchical Maps, Calls, the table games, and other optional capabilities moved into **downloadable packages** with package-owned server runtimes (25,000+ lines removed from base; capability registries and compatibility bridges remain). See "Downloadable Agents (v2.3)" below.

## The Core Objects

### Character
A persona the user chats with. Follows the V2 character card spec. Stored as JSON in the file-native store (`DATA_DIR/storage`). Fields include `name`, `description`, `personality`, `scenario`, `first_mes`, `system_prompt`, plus Marinara-specific extensions (appearance, backstory, name/dialogue colors, schedule, etc.). Can be created in the app, imported from SillyTavern, imported from PNG files with embedded metadata, or browsed from Chub.ai via the **Card Browser** (renamed from "Bot Browser" in v2.3; "Browse Online" is now **Download Cards**, opening as "Cards Library" in the unified library shell; since v2.4.2 the Characters and Personas panels have split **Download / Open Library** controls). *(v2.5.0, #7072)* **CharacterTavern can't be browsed** in the Card Browser for now (its rebuilt site dropped the connection Marinara used) — its cards still import as files.

See `references/character-cards.md`.

### Persona
The user's own identity in chats. Same shape as characters but simpler. Has name, description, personality, appearance, avatar, and optional custom colors. Multiple personas per user; the persona **selected for that chat** is substituted for `{{user}}` macros in prompts. **↺ No global active persona (v2.4.6, #6206–#6208):** the global active-persona default was removed — chat identity follows the chat's own persona selection, and a chat with **no persona selected stays anonymous** (the generic name "User", no persona details) in **every** mode, Conversation included. (Earlier guidance said only Roleplay stayed persona-less and Conversation fell back to the globally active Persona — no longer true.) Guide: `docs/characters/choosing-your-persona.md`.

### Lorebook
A keyword-triggered knowledge base. Entries have `keys` (trigger words), `content` (what gets injected when a key is matched in recent chat context), and a bunch of tuning knobs (sticky, cooldown, delay, selective, grouped, recursive). Can be global, per-character, or per-chat.

See `references/lorebooks.md`.

### Preset
A full prompt configuration. Controls the order and content of system prompt sections, generation parameters (temperature, top-p, max tokens), and optional choice blocks. The default is **Marinara's Universal Preset v12** (`packages/server/src/db/default-preset.json`), and as of v2.0 presets carry prompts for **Conversation and Game modes** too, not just roleplay. The stock Universal Preset is **protected** (v2.4.2–2.4.3, #4871/#5142): it can't be deleted or edited directly and is restored if changed — its editor offers **Create editable copy** instead. *(v2.5.0, #7006)* Any **Prompt Block** can be switched to **Send without wrapper** (Sections tab → expand the block): it is sent exactly as written, without its XML tag or Markdown heading, while the rest of the preset keeps its wrap format (a wrapping group can still surround it; markers always keep their wrapper). A preset's **Regex** tab holds scoped-regex defaults that its chats inherit unless they set their own override (v2.4.6, #5774). Parameter panels show each **effective** generation value and which source won — preset, connection, chat, mode, or output cap (v2.4.6, #6052; `docs/prompts/generation-parameters.md`).

> **⚠️ Vocabulary change (v2.4.0) — get this right.** Reusable **Chat Settings Presets** were renamed **Settings Profiles** throughout Chat Settings, Roleplay quick setup, import/export, localization, and the docs. The word **preset** is now reserved for **prompt presets** (the object described above). A *settings profile* bundles reusable chat configuration; a *prompt preset* shapes system-prompt structure and generation parameters. Existing exported profile files remain importable. Use the correct term when advising — the UI and docs now distinguish them, and saying "preset" for a settings profile will send the user to the wrong panel. Guides: `docs/chats/settings-profiles.md`, `docs/prompts/presets.md`.

**What a settings profile holds** (`docs/chats/settings-profiles.md`): connection, prompt preset (the "prompt source" in Conversation), agents and tools, translation, Memory Recall, Advanced Parameters, *(v2.5.0)* the **window and button layout** plus whether the layout tips are hidden (see The Chat Surface below), and other reusable chat options. It does **not** carry chat-owned content — characters, persona, lorebooks, sprites, summary, tags, scene prompt — nor the conversation history. A profile saved before layouts existed (including the built-in **Default**) leaves the chat's layout alone.

Constraints to state when recommending one:
- **Profiles work in Conversation and Roleplay only. Game mode does not show the profile controls.** Recommending a settings profile to a Game-mode user is advice that cannot be followed.
- A prompt preset is **one item inside** a settings profile, not a competing alternative to it. There aren't two rival preset systems.
- Profiles stay within the chat mode they were saved in (v2.4.2, #4849; legacy Visual Novel profiles migrate to Roleplay on import). Each mode has one built-in **Default** profile, and a star beside the Profile dropdown makes a profile the default for new chats in that mode. Separately, the Conversation and Roleplay **setup wizards** can save their own mode-specific defaults independent of profiles (v2.4.6, #5948).

*(v2.3.5)* The Chat Settings **Prompt Preset** area was reworked: Roleplay shows the preset-section editor directly once a preset is selected (no collapsible toggle); Conversation and Game show the effective prompt inline — editable in place, expandable to a full window, with a macro browser — and the redundant "open selected preset" shortcut was removed. Chat Settings also remembers which sections you left expanded.

### Connection
An API configuration pointing at an LLM provider: provider name, API key (encrypted at rest with AES-256), model, base URL, max context length. Users need at least one connection to chat. Per-chat overrides are supported. Besides LLM providers, `apiProviderSchema` (`packages/shared/src/schemas/connection.schema.ts`) has four **special connection types**: `image_generation` and `video_generation` (v2.1; handled by the media services, not the LLM provider registry), **`audio`** (v2.4.3) and **`decision`** (v2.5.0), both below. Root-level connections can be reordered by drag or moved into folders via a saved Custom sort order (`connection.ts sortOrder`, `connection-folders.ts sortOrder`) (v2.1). The compact **Defaults** section (v2.2) lets each category — **Main, Agents, Images** (renamed from "Illustrator" in v2.3)**, Videos, Audio** (v2.4.3) — set a default/fallback connection; a failed generation retries once through that category's fallback (with a toast naming the fallback connection/model), while user cancellations and already-streamed partial text are protected from duplicate output. Defaults → Agents also holds the agent bulk-assignment control and the paid-default warning toggle (v2.4.6, #5767).

- **The model lives on the connection** *(v2.5.0, #7098)*: switching it from the **Connections** menu beside the chat input (search/type an ID, star favourites, refresh) or Chat Settings → Connection → **Model** saves it to the connection, so **every chat, agent and helper using that connection switches too**. Warn users before they change the model on a shared connection.
- **Random pool** — the shuffle icon on a connection row adds it to the pool; Chat Settings → Connection → **🎲 Random** (**GM / Party Model** in Game) or the dice in the Quick Connection Switcher picks a different pooled connection per reply, so there's no single model to set. Connection exports never include API keys (`docs/connections/organizing-connections.md`).
- **Rate limits** (v2.4.3, #5183): HTTP 429/529/503-with-`Retry-After` pauses and auto-resumes the same request (Mari included); an optional per-connection **Max Requests Per Minute** (`0` = unlimited) paces bursty callers in advance. **Max Parallel Agent Jobs** caps concurrent agent calls per connection (v2.4.2, #4950) — both matter for capped proxies driving Mari or many agents. After three consecutive provider failures an automatic-generation connection is quarantined for six hours while foreground chats keep using it (v2.4.2, #4769).
- Image connections accept custom JSON parameters such as LoRA fields (v2.4.6, #6167) and optional image-prompting instructions applied when selfie/Illustrator prompts are written (v2.4.2); language connections accept validated, non-secret custom HTTP headers (v2.4.6, #5910). Connection switchers show the latest measured context usage (Advanced → **Show context usage**, on by default; v2.4.5). *(v2.5.0, #6960)* The chat's **Image Captioning** prompt is editable in Chat Settings, and a captioning failure now stops the reply instead of silently sending the raw image.

**Audio connections (v2.4.3, #5146/#5156) ↺** — speech backends are now a connection type. An **Audio** connection carries the **Audio Source** (ElevenLabs, OpenAI-compatible, PocketTTS, xAI Voice), base URL, key, model and **Default Voice**; ElevenLabs adds **Game sound effects** / **Game music** switches. Speech, voice discovery and Game audio resolve explicit pick → **Connections → Defaults → Audio** → fallback. A one-time boot migration turned a configured legacy TTS settings blob into a default audio connection (a blob with TTS switched off migrates to none, so an upgrade never re-enables TTS). The Connections → **Text to Speech** card still holds voice assignment and playback settings, and its own Source / Base URL / API Key / Model — but those apply **only when no Audio connection exists**: any explicit, default or fallback Audio connection overrides them, while the card's **Enable TTS** switch still gates default/fallback speech (`tts.routes.ts` `resolveAudioConfig`). `docs/media/tts-setup.md` and `docs/conversation/calls.md` still put the key on the TTS card (docs lag code). Guide: `docs/connections/providers-reference.md` (Audio).

**Decision model (v2.5.0 headline, #6530/#6569/#6559)** — an optional small model that scores a statement about the recent messages (0–1 against a threshold → yes/no) or picks one answer from a short list; it never writes chat text. Pick it under **Connections → Connection defaults → Decision model** (the panel heads that section **Defaults**; default **None**): a local model you already run (**Primary** / **Utility local model**), a **Decision connection** (TypeSafe/Jev, OpenRouter, a Custom System One endpoint, or an **OpenAI-compatible chat model** such as Ollama/LM Studio), or the experimental **Decision sidecar** (Open-Jev; Linux x86-64 + NVIDIA only — on Android use a hosted connection). It drives custom-agent **activation questions**, `{{#if decision:"…"}}` / `{{#if decision_choice:"…" == "…"}}` prompt statements, lorebook **Decision** fields, and opt-in Smart response order. **Advanced Memory Recall ignores this default** — it uses its own per-chat **Use Decision model** switch plus a **Memory Decision connection**, which must be a Decision connection (local slots aren't offered); misses or answers slower than 10 s fall back to ordinary recall. With no model or no answer each feature falls back (statements read as no; activation questions don't block). For activation questions and prompt/lorebook statements it sees **only the statement and recent messages** — never the preset, cards, persona, lorebook or @Depth inserts; Smart response order also sends a short roster (name, status, activity, talkativeness, ≤300 chars of personality/description), and Advanced Memory sends its own transcript/recap batches — hosted providers receive all of it. Full model: **`references/conditional-prompts.md`**; engine guide `docs/connections/decision-models.md`.

### Agent
An autonomous LLM sub-system that runs during generation. As of v2.3, optional agents are **downloadable packages** installed from the official catalog (39 packages on the stable catalog at the v2.5.0 sync, grouped in the UI as Apps / Writer / Tracker / Misc — see "Downloadable Agents (v2.3)" below); **fresh installs contain none**. User-defined **custom agents** remain, and run in Conversation, Roleplay, and Game whenever agents are enabled (v2.3, #3692). Each agent has a phase (pre/parallel/post), a system prompt, an optional dedicated connection, and settings. All disabled by default — users enable only what they need. Each chat also has an **Enable Agents** master toggle (v2.3) gating all agent initialization and model calls: off means no selected agent (including package services) initializes or calls a model; the setting survives upgrades without re-enabling.

See `references/agents.md`.

### Custom Tool
A user-defined function the main chat model can call during generation. Three execution types: `static` (hardcoded response), `webhook` (POST to a URL), `script` (sandboxed JS, no network; **off by default** — needs `CUSTOM_TOOL_SCRIPT_ENABLED=true` on the server). Exposed to the model as OpenAI-compatible function definitions.

See `references/custom-tools.md`.

### Impersonate & guided generation

Two per-chat generation modes; guide `docs/chats/guided-and-impersonate.md`.

**Impersonate** — the model writes the *user's* turn. Per-chat fields in `chat.schema.ts`: `impersonate`, `impersonatePromptTemplate`, `impersonateConnectionId`, `impersonatePresetId`, `impersonateBlockAgents`. *(v2.4.0)* refined with **server-backed prompt templates shared across browsers** (so a template set on desktop is there on mobile), read-only built-in previews, full-view editing, and a direct link to Quick Replies settings.

`impersonateBlockAgents` is the architecturally interesting one: an impersonated turn can deliberately **bypass the agent pipeline**, so trackers and post-processors don't fire on a turn the user didn't really write.

**Guided generation** — `generationGuide` and `generationGuideSource` on the chat feed `buildGenerationGuideInstruction` (`packages/server/src/routes/generate/`), which injects a steering instruction for the next reply. This is what backs the `/guided` slash command. Note that guided replies fire **Chat reply** lorebook triggers, not a separate trigger type (see `lorebooks.md`). *(v2.5.0, #7060)* Guided regeneration leaves the direction in the chat box for another try unless **Keep guidance after regenerating** (Settings → General → Input & Editing) is off.

Related per-chat fields worth knowing: `daySummaries` (a day-level summary structure, distinct from Chat Summary — see the memory-surfaces table in `agents.md`) and `continueAddsNewline` (whether `/continue` inserts a newline).

### Personal Extension (removed v2.3.4 → **reintroduced sandboxed in v2.3.5**)
The old full-trust client extension feature (runtime CSS + JS with a scoped `marinara` API) was removed in v2.3.4. **v2.3.5 brought extensions back in sandboxed form**, and v2.4.0 expanded them (Browser Extension API v5, host-rendered UI contribution slots, a Full page access compatibility mode for legacy External Extensions).

Browser code runs in a Worker inside an opaque-origin sandboxed iframe with no Marinara DOM, origin, or network access; server code runs in a separate Node process under macOS Seatbelt or Linux Bubblewrap (unavailable on Windows/Android, where it fails closed). Professor Mari authors drafts; only the user can approve the exact SHA-256 hash. Third-party imports live in a separate **External Extensions** section behind two gates (`ENABLE_EXTERNAL_EXTENSIONS=true` plus a Danger Zone opt-in).

Schema: `packages/shared/src/schemas/personal-extension.schema.ts`. Injector: `packages/client/src/components/layout/PersonalExtensionInjector.tsx`. See `references/extensions.md` for the full model — don't answer extension questions from this summary alone.

### Professor Mari (built-in assistant)
Marinara's built-in assistant, seeded at first run and not deletable. **As of v2.0 she is the Home-screen assistant** (no longer a normal Conversation-mode character): users talk to her from the Home screen, where a Pi-backed *workspace agent* can inspect the local app, create and edit content — characters, personas, lorebooks, presets (section by section since v2.4.2), themes, agents, chats, Personal Extension drafts — and navigate panels. She replaced the standalone character/persona/lorebook *maker* modals and their generation routes, removed in v2.0. v2.3 removed the per-editor AI Write controls (with their separate model connection/source settings) and routed Conversation **About Me** drafting through Mari; since v2.4.5 the Character Editor's Conversation profile again has **Generate About Me from this card** / **Generate Conversation behavior from this card** buttons, so Mari is one of two routes (personas still go through her). About Me and the `update_about_me` tool remain Engine built-ins, not packages.

**How her changes get approved ↺** (the old "browser approval for database changes" summary is out of date):
- **Permissions Mode** (v2.4.6, #5725): **Auto** (default — she judges from your words and saved memories), **Manual** (describes first, stages only after you accept), **Accept edits** (record edits apply without a review card), **Plan** (changes nothing — mutating commands are refused server-side; she lays out the exact edits in chat), **Bypass permissions** (no asking, no cards). Per Mari chat via the shield button in her header; global default in **Settings → General → App Behavior**. In every mode, deletions and sensitive changes keep their review.
- **Keep/Restore review cards**: edits *and* creates (v2.4.2, #4825) apply first, then show **Review Mari's changes** with a readable before/after Easy Viewer (#4919); **Restore** reverts. Cards survive restarts and auto-close after 14 days with the change kept (#4828; 50 pending reviews max). *(v2.5.0, #6842)* Cards belong to the Mari chat that made the change — a new chat starts clean, deleting that chat keeps the changes and drops its cards, and a no-op edit makes no card; her own built-in card isn't editable (reset every start). The v2.4.3 server-side pre-execution authorization gate (#5093) was removed in v2.4.6 (#5721): an intent-phrased edit lands straight in a review card, and once she asks whether to apply, later edits wait behind **Accept** / **Don't apply** (#5748, #5820).
- **Sensitive file changes** (dependency files, launchers, installers, CI) wait for **Apply change**; npm dependencies wait for **Install**; raw package-manager installs are blocked in her shell. *(v2.5.0)* `mari code check` runs inside her shell sandbox with no network or server secrets (no sandbox → she asks you to run `pnpm check`); she can't read or change the API-key key file or `.env`, can read but not write the built `dist` folders (#7003; only `mari code check` rebuilds them), and her shell can't write into the data folder.

**Saved Memories (v2.4.2, #4851)** — her own persistent memory of standing preferences, distinct from every chat memory surface in `agents.md`. Saved memories override her defaults (e.g. opting back into edit-without-asking). Only a title/description index of *enabled* memories sits in her prompt and full text is fetched when relevant; **Persistent** memories inject their full body every turn (keep them few and small). Memories she writes land **disabled** until **Keep & Enable** or the **Memories** panel turns them on. She can also read an attached chat (all, a range, or the last N messages; v2.4.3, #5073) and author Decision activation and conditional prompts (v2.5.0, #6629).

**Custom Skills** — user-written instruction documents that change how she handles a kind of request (header **Skills** button → **Professor Mari Skills**: **New** from a template or **Upload** a `.md`/`.txt`; Name / Description / Instructions; per-Skill on/off). Distinct from Saved Memories (standing preferences); at phone widths both share one **Skills & Memories** button (v2.4.6, #5741). A Skill that merely explains Decision syntax isn't permission to add Decisions.

See `references/character-cards.md` → The Professor Mari Pattern, and `docs/home/professor-mari.md`.

## Downloadable Agents (v2.3)

v2.3.0 restructured the engine around **downloadable capability packages**. Optional agents no longer ship in the base Engine — they install from the in-app **Agents → Download Agents** library, backed by the official **Pasta-Devs/Marinara-Agents** catalog — **39 packages on the stable catalog at the v2.5.0 sync** (6 writer / 13 tracker / 20 misc by catalog category). The catalog changes independently of Engine releases, so check Download Agents (or ask Professor Mari) for the live list. *(v2.5.0, #6943)* The UI groups packages as **Apps** (packages that open their own Home tab — Noodle, Slurp, Gacha Forge, …; each asks for a restart after install) / **Writer Agents** / **Tracker Agents** / **Misc Agents**. Official Game Mode **rulesets** also install here, marked **Rules**. Key points:

- **Fresh installs ship no optional agents**; upgrades from ≤2.2 migrate agent selections, settings, and history automatically. Package-owned server runtimes: see "Package split" at the top.
- **Lifecycle ↺** — Marinara checks installed official packages against the catalog and **asks before downloading each compatible update** (the v2.3.1 silent startup auto-upgrade was replaced in v2.3.5; since v2.4.6 the prompt lists release notes and a dot marks a noticeable change). **No** keeps the current version and leaves **Update** in Download Agents. Packages live in `DATA_DIR/capability-packages`; offline, declined, incompatible, missing, or failed updates keep the previous version; verified runtime failures roll back automatically; incompatible versions are quarantined before their hooks can crash generation (#3647).
- **Capability API** — introduced as 1.3 in v2.3 (#3690) with host services for packages (safe model routing, persistence, history/checkpoints, resources, logging, transactions, client contribution loading, visible readiness/retry states); now **Capability API 1.66 (v2.5.0)**. Notable steps: 1.8 `game-surface` Game Experiences, 1.10 package assets, 1.15 `runtime.resolveEmbeddings()`, 1.20 package kind `ruleset`, 1.31 host LLM/image/video integrations, 1.50 Mari package actions, 1.66 `api.registerSceneOrigin` + `scenes` permission (a package can start a Roleplay scene from its own thread, e.g. a social-app DM, #7118). Packages holding the `prompt-context` permission contribute text to each turn's system prompt (v2.4.1, #4526), and Roleplay tracker packages can place prompt blocks through preset Agent sections (v2.4.4, #5408).
- **Mode badges** — the catalog shows Conversation/Roleplay/Game compatibility badges and supports search by mode (v2.3, #3676).
- **Per-major catalog lanes** (v2.3, #3712) — each Engine major installs/updates only from its matching lane: `catalog/v2/catalog.json` for Engine 2, `catalog/v3/` for Engine 3, with `catalog/catalog.json` as a legacy v2 alias.
- **Custom GitHub agent repositories** (v2.3.4, #3861) — a disabled-by-default third-party agent-source path alongside the official catalog: manual preview/apply (no auto-sync), explicit per-repo trust confirmation, stable sync identity, and bounded SSRF-safe archive validation.
- **Import/export hardening** (v2.3.4, #3953) — imported agent files can no longer install bundled custom functions, grant themselves tool access, or overwrite a curated Agent by reusing its internal type; exports no longer bundle function definitions, imports land under a fresh custom identity, and the user must review and explicitly re-attach tools.

See `references/agents.md` for the package catalog and per-agent details.

## The Chat Surface (v2.5.0)

**Chat Settings is a movable window holding the chat's tools** (v2.5.0, #7034/#7036). A sliders button inside the chat (starts top-right, draggable) opens it; each chat remembers button and window positions. On computers windows move, resize, **Pin** (stay open, reopen after refresh) and **Lock**, and any section can **Pop out** into its own window (closing shrinks it to a movable button; **Put back in Chat Settings** returns it). Phones get full-width panels plus a movable **Chat tools** three-dot menu. Game controls, Connected chat and package controls open from movable buttons too. Title bar: **Help** (`?`), **Reset View**, the **favorite layout** star (default arrangement for new chats in that mode; a settings profile's saved layout overrides it), and the Roleplay **Tracker Panel** die. Former side tools are now sections (still called *drawers*): **Search messages**, **Chat Branches**, **Chat Summary**, **Active Context**, **Agent activity** (agent runs, retries, Advanced Memory progress), **Author's Notes**, **Gallery**. On upgrade, existing chats keep their tools as movable buttons (trackers grouped in a **Trackers** window) and that arrangement is starred once for new chats in each mode; fresh installs start with everything inside Chat Settings. Guide: `docs/chats/chat-settings.md`.

**Message marks** (v2.5.0, #6698/#6895) — each message's **Bookmark, pin or note** menu: **bookmark** a moment to find later; **pin** up to **ten** messages so the model keeps them past the history limit (pins survive swipes; restores refuse to exceed ten); attach a **private note** that stays out of prompts — unless, in Roleplay, **Show the note to the narrator character** hands it to that one character — and out of exports unless **Include private notes in exports** is on. **Recover deleted chat messages** (Settings → Advanced → Features, off by default) keeps deleted messages in a **Trash** for 30 days; Game Mode deletion stays permanent. Search messages has **Bookmarks** and **Trash** tabs (and, since v2.4.6, #6090, jumps to a number typed as `#67`). Also new (#6698): cross-chat search with phrases and filters, chat statistics, and readable **Markdown / HTML transcript export** (hidden and internal content excluded).

## Chat Modes

Marinara has **exactly three chat modes — Conversation, Roleplay, Game** (`chatModeSchema = z.enum(["conversation","roleplay","game"])`, `packages/shared/src/schemas/chat.schema.ts`, unchanged at v2.5.0). Each has a different prompt assembly pipeline and UI. **↺ Two things that look like modes are not:** **Visual Novel** is a Roleplay *display style* (v2.4.6), and **Noodle** and **Slurp** are downloadable **App** packages that open in Home tabs (see "Apps: Noodle and Slurp" below). Earlier guidance listed Noodle as a fourth mode — it isn't one.

### Conversation Mode 💬
Discord-style DMs. Casual text, no asterisks, no narration. Characters have:
- **Schedules** — weekly timetables of activities, generated by an LLM based on personality. A global IANA **timezone selector** (v2.3; browser-detected default, overridable, device-syncing) is honored by schedule generation, presence, autonomous messages, temporal prompt context, and background polling — a blank `TZ=` inherits the host timezone (#3590). Routine-summary generations use an 8,192-token default (up from a 512-token ceiling) with low reasoning effort requested (v2.3, #3696). Schedules are **character-owned** and apply across all of that character's chats, with per-chat opt-outs (v2.4.4–2.5.0, #5358/#6481); enabling schedules no longer starts generation. The **Character Schedule Manager** (calendar icon beside the activity field, v2.4.6) bulk-generates or removes schedules without an open chat, and **automatic weekly renewal is off unless enabled per character there**. The editor can generate a week one day at a time (v2.5.0). Guide: `docs/conversation/schedules.md`
- **Statuses** — derived from schedule: online, idle, dnd (do-not-disturb), offline
- **Talkativeness** — 0–1, affects autonomous messaging rate
- **Commands** — every in-message command is a per-chat switch under Chat Settings → **Commands** (behind a master **Commands** toggle, on by default): **Schedule Updates** (`[schedule_update: …]` changes the character's current status/activity), **Cross-Post** (`[cross_post: target="…"]` redirects a message into another shared chat), Selfies, Memories, Scenes, Music, Haptics, Influence, **Notes** (see Connected chats), Calls, Reactions, plus installed games. Package-owned ones (Selfies → Illustrator, Calls, Music → Music DJ, Haptics, games) appear only once their package is installed (`CONVERSATION_COMMAND_AGENT_IDS` in `packages/shared/src/types/chat.ts`)
- **Selfies** — `[selfie]` / `/selfie` generate a selfie-style image; needs the **Illustrator** package and a **Selfie Connection** (Chat Settings → Agents → Illustrator Settings). Guide: `docs/conversation/selfies.md`
- **Memory commands** — characters send memories to other characters via `[memory: target="…", summary="…"]` (both fields required; a target-only tag doesn't match)
- **Scenes** — conversation characters can initiate temp roleplay chats via `[scene: ...]`. A scene-prompt setup dialog for user- and character-initiated scenes remembers POV, tense, and optional prompt wishes for the next scene generation (v2.2); it also remembers the prompt preset and asks its variables first (v2.4.6) and picks the scene's persona and characters, whose autonomous messages in the source Conversation pause until the scene ends (v2.5.0)
- **Turn games** — six Conversation table games, **downloadable packages** with package-owned runtimes since v2.3: they surface as **Commands** toggles (no Add Agent entries) and installed games hot-activate their slash commands without a restart (#3699). Each has an in-character setup, a `[command]` token, a slash command, bot turns and board state (route `/api/turn-games`): `[uno]`, `[chess]`, `[poker]` (No-Limit Hold'em, 2–8 players), `[eightball]` (2D-physics 8-Ball Pool, `/8ball` or `/pool`), `[tic_tac_toe]` (`/ttt`), `[rock_paper_scissors]` (`/rps`); `/games` opens the picker
- **Emoji** — Discord-style `:shortcode:` emoji with autocomplete alongside custom emoji (v2.2, #3515)
- **Reactions (v2.1)** — `[react: emoji="😂"]` badges the user's latest message; `[react: emoji="🙄" to "Character Name"]` reacts to another character (or one segment of a merged reply). Conversation-only, gated by a per-command **Reactions** toggle; grammar in `character-commands.ts` REACT_RE.

Group DMs are supported. As of v2.3.4 (#3887), multi-character Conversations offer **Grouped and Individual response modes** with sequential, smart, manual, mention-directed, and autonomous character selection, a shared daily check-in budget, and a token-use warning — superseding the v2.3.1 single-merged-generation-only model. In Grouped mode the bubble display still splits lines per speaker with inherited identity (#3609). Mentions always select the mentioned responder(s); the Reply When Mentioned toggle was removed (#3891) — `docs/chats/group-chats.md` still documents it and no Grouped/Individual choice for Conversation (docs lag; code wins; its Roleplay half is current). Conversation chat check-in ceilings accept explicit numeric overrides (v2.3.4, #3864). *(v2.5.0)* In **Individual** mode a character can hand the next reply to another with an @mention (one reply per character per turn queue, so no loops; #6567), replying to a character's message selects them like an @mention (#6978), the shared daily check-in budget is paced across the group (#7055), and **Character Exchanges** (characters talk to each other while you're away) work with schedules off. **Smart** selection runs on the default Agent connection (v2.4.2, #4765) and can optionally ask the Decision model instead — one yes/no per candidate (**Also use it to pick who speaks in Smart response order** under Decision model; #6559). Guide: `docs/chats/group-chats.md`.

**Calls (v2.1; downloadable package since v2.3)** — Discord-style audio/video calls inside Conversation chats. As of v2.3 this is the **`conversation-calls` package** — renamed user-facing to "Calls" with package IDs and the `/api/conversation-calls` route path preserved — and it must be installed from Download Agents (see Downloadable Agents (v2.3)). **Local Whisper is Calls-owned**: Connections → Local Model shows the Local Speech Model controls only while the package is installed, and uninstalling removes downloaded Whisper models. Gated globally by the **Call Audio Pipeline** switch (`ttsSettings.callAudioEnabled`, default false; Chat Settings → Agents → Calls, global across chats) plus the per-chat **Audio/Video Calls** opt-in. Characters can initiate **incoming calls**; the call surface has a call-only chat, mute / camera / screen-share, a soundboard, call history cards, and a **post-call summary** injected back into the chat. Guide: `docs/conversation/calls.md`.
- **Voice input** — `callAudioInputMode` (default `local_whisper`) selects the mic path: `system` (provider-native audio), `auto`, `transcribe` (browser speech recognition), or `local_whisper` (Whisper Tiny/Base). `callVideoInputEnabled` (default false) gates camera/screen-share.
- Character **video presence** in calls, the **Sprites → Clips** editor, and the in-call `[custom_clip: …]` / `[react:]` commands are covered in `references/character-cards.md`.

### Roleplay Mode 🎭
Traditional creative-writing roleplay. Rich narration, prose. Supports:
- Full agent stack (world state, trackers, sprites, backgrounds, weather, combat)
- VN-style character sprite overlays — a chat can show all enabled sprite owners (the hard-coded 3-sprite cap was removed in v2.1)
- Scene videos (v2.1) — per-image **Animate** / Gallery Video actions (see Game Mode → Scene videos)
- Custom backgrounds with crossfade transitions
- Weather particle effects (rain, snow, thunderstorm, fog, cherry blossoms, aurora)
- Time-of-day lighting (dawn, day, dusk, night)
- Game HUD with character stats, quests, world state
- Model thinking in a collapsible field above each reply (Appearance → **Show Thinking In Messages**, v2.4.4)
- **Chat position** Left / **Center** (default) / Right on wide screens — Settings → Appearance → Roleplay → **Roleplay Presentation** (v2.5.0, #7106); phones and Game unchanged

**Visual Novel is a Roleplay display style, not a mode ↺** (v2.4.6, #6044). The VN *chat mode* stays retired — v2.2 routed legacy/imported VN chats under Roleplay, and v2.4.0 (#4368) removed the mode identifier and its compatibility branches outright. But Roleplay now has an optional **Visual Novel display**: choose **Classic** or **Visual Novel** during Roleplay setup or in **Settings → Appearance → Roleplay**. It shows completed paragraphs above the composer with dialogue portraits and sprites, steps through a turn with **Previous / Next paragraph** (optional timed auto-play that waits for speech), and keeps the full transcript and message actions behind a history arrow. So never offer VN as a *mode*, but do offer the VN *display* to a user who wants a VN-style Roleplay. Game dialogue labels use "Dialogue Box" wording.

**Group Roleplay** — **Merged (Narrator)** (default: one reply voices every character plus narration) or **Individual** (one character per reply; Response Order Sequential / Smart / Manual). Switching changes the whole prompt at once (v2.5.0, #6959). *(v2.5.0)* In Individual mode a character can hand the next reply on with an @mention (#6567; one reply per character per turn), and with Smart or Manual order the response menu starts with a one-off **Smart** pick (existing model or Decision model) that leaves the saved order unchanged. Shared or per-character **New Start** markers let a newly introduced character begin from a later message without truncating the rest of the cast's history (v2.4.2, #4905).

**Roleplay Commands (v2.4.6, #5990/#6039/#6069/#6175)** — opt-in in-message commands. Under **Chat Settings → Agents → Commands**, turn on the master **Commands** switch, then each command's own switch (all start off): **Illustrations**, **Documents** (in-world note, letter, journal, report, poster or terminal — the model writes plain text, the engine styles it), **Sound Cues** (needs an ElevenLabs Audio connection with **Game sound effects** on; own **Sound effects connection** picker), **Soundtrack**, **Personal Notes** (`[notes: content="…"]` — motives, secrets, lies and plans that persist across turns, visible only to their character and the appointed narrator), **Reminders** (newest three active per character), **Rolls** (real engine dice before narration continues, with the character's RPG attribute modifier; optional situational modifier and DC since v2.5.0, #6417), **Direct Messages** (in-world DMs into a Conversation thread), **Whisper** (*v2.5.0, #6616*; `[whisper: character="name" text="…"]` — only the recipient and the appointed narrator receive it; users can whisper too, also in edited messages, #6918), **Interruptions** (`[interrupt: part="a verbatim phrase of at least three words"]` cuts off the previous message), and **Combat**. Illustrations, Soundtrack and Combat need the Illustrator, Music DJ and Combat agents installed **and** active in the chat. Whisper, Documents, Rolls and Combat each have a **Who can …** choice (All / Narrator); narrator-only use needs a **Narrator character** chosen and Individual group mode. Notes, reminders and documents follow the selected swipe; Personal Notes, Reminders and Whisper need a solo chat or Individual group mode. *(v2.5.0, #6945)* A `roll_dice` tool added under Function Calling now really rolls in Roleplay, honouring **Who can roll dice**. Reach for these **before** custom tools, agents or chat variables when a user wants a character to keep secrets, write letters, or roll dice. Guide: `docs/roleplay/getting-started.md`.

**Advanced Memory Recall** (v2.4.6 Alpha, #6102; out of Alpha in v2.5.0) — opt-in, **Roleplay-only** automatic context management (Chat Settings → Memory Recall → **Advanced Memory Recall**, or **Automatic context and memory handling** in the Roleplay setup wizard). It manages the live history window, scene summaries and relevant old excerpts together, independent of the Agents switch and with no package. **It and basic Memory Recall are mutually exclusive** — enabling one turns the other off (#7150). Presets get a **Recalled Scenes** marker (`recalled_scenes`; old `recalled_messages` markers are aliases). See the memory-surfaces table in `references/agents.md` and `docs/agents/memory.md`.

**Chat Summary (v2.2)** — the Summary Connection has a maximum-output-size setting (chat `summaryMaxTokens`, clamped by `CHAT_SUMMARY_OUTPUT_TOKENS` in `packages/shared/src/types/chat.ts`: 1–32,768, default **4096** tokens) applied to both manual and automatic summaries. A custom Roleplay Chat Summary prompt now applies **globally** across all roleplay chats, not only the currently open chat. v2.3 removed the 2,000-char per-source-message truncation and the 64 KiB compiled-summary ceiling in `chats.json`. v2.3.4 (#3864) removed the 50-message ceiling on Conversation and Roleplay recent-summary tails (conservative defaults and cost guidance retained). Later: older summaries can be retrieved semantically while recent ones stay in context (v2.4.4, #5240), and Roleplay Chat Summary can generate several explicit message ranges as separate chronological batch entries (v2.4.6).

### Game Mode 🎮
A shipped mode (v2.0) — Roleplay + JRPG game loop. The model acts as GM; the engine handles mechanics. State machine with `exploration`, `dialogue`, `combat`, `travel_rest`. Tactical combat UI, dice rolls, skill checks, reputation, elemental reactions, quest tracking, auto-journaling. v2.0 also added a Roleplay HUD / Tracker Panel with **editable field locks** (manually pinned tracker values survive generated updates; v2.1 hardened this so tracker/custom-agent update agents can't bypass a locked field by renaming or replacing the locked row at the same position), **Game-Mode custom-agent selection** in Chat Settings, and a setup wizard. Automatic checkpoints are captured at session start/end and combat start/end, but **there's no in-app restore** (only `POST /api/game/checkpoint/load`) — don't offer one as an undo. Routes: `/api/game`, `/api/game-assets`.

**New Game wizard** — seven steps: **Connection** (GM connection — the only required field — plus a scene-effects connection defaulting to **Local Model (Gemma)**), **World** (genre, tone, difficulty, rating, language, Combat Preference, Rules), **Party** (persona, party, and **Game Master Mode**: **Standalone GM** default, or **Character GM** using one of your cards), **Goals**, **Lorebooks**, **Features** (Visual Generation off, Music DJ off, Custom HUD Widgets on, Start Muted off), **GM** (**Game Presentation** Standard or **Storyboard Optimized**, which only shapes GM narration). World generation is **one strict-JSON call** — use a capable paid model (free/auto-routing and small open-weight models usually fail); a **Repair JSON** modal fixes near-miss output without a paid retry. Guide: `docs/game/getting-started.md`.

**Tactical Combat (v2.3)** — a **Combat Preference** (setup wizard; changeable via Chat Settings → Combat Style) chooses between classic narrative combat and **tactical grid-RPG battles**: a terrain-painted battlefield with scene-matched backdrops, unit classes, party formations, per-unit movement/attack ranges, counters/crits/misses, and a full enemy phase on a deterministic seeded engine at four difficulty levels — with animated movement, damage popups, a draggable unit inspector, staged translucent move previews, restartable encounters, and a mobile layout. Distinct from the downloadable `combat` agent package.

**Rulesets and the Rules choice (v2.5.0)** — a Game Mode **ruleset** is one JSON data file (no code) describing a tabletop system: `resolution.kind` `dice-sum` or `dice-pool`, a character sheet, rests, items, optional fight blocks, bestiary. Once one is installed, the New Game wizard's World step shows a **Rules** choice below Combat Preference (default **Marinara's own rules** — the built-in d20 checks and six-attribute sheet). The ruleset is fixed for the game's lifetime; party sheets are copied in at world generation and nothing writes back to the card. Checks then use the ruleset's dice, the GM records spending and damage with a validated `[sheet: …]` command, and a ruleset that resolves its own fights does so server-side — Combat Preference then picks **Classic** (no positions) or **Tactical** (board). Official rulesets install from Download Agents (marked **Rules**); community ones import from a file behind **Allow custom Agent imports**. Full model and authoring: **`references/rulesets.md`**; engine guides `docs/game/getting-started.md` (Choosing rules), `docs/extending/writing-rulesets.md`.

**Game Experiences (package-provided game surfaces; v2.4.1+, Capability API 1.8+)** — a capability package can supply an entire Game mode by declaring the `game-surface` slot: it draws its own HUD, menus and combat over the shared narration and declares which built-in systems it replaces (anything undeclared stays built-in). It's chosen from the **Experiences** block of the New Game wizard, for new games only, and fixed for the game's lifetime; Experiences can prepare their world before the opening narration from hand-picked lorebook entries (v2.4.6). This is the supported way to add a new *game* experience without forking — `docs/development/optional-agent-packages.md`.

**Real dice (v2.4.6)** — Game Mode rolls real dice instead of letting the GM invent numbers: every Game turn carries the dice tool even with Function Calling off, the engine rolls every requested skill check with the player's own sheet modifiers (overwriting GM arithmetic that doesn't add up), and rolls show as animated dice cards kept per swipe. Chat Settings → Function Calling has **Narrate dice outcomes immediately** (on by default; off skips the extra rewrite request) and **Finish rolled turns in one request** (off by default; the GM writes both outcome branches or a `[[roll: 2d6+3]]` placeholder and the engine fills in the number, so a rolled turn costs one request). Game chats can also use a separate tool-planning connection and **Let the GM search lore**. Guides: `docs/game/dice-and-skill-checks.md`, `docs/game/getting-started.md`.

**Inventory, audio, setup switches** — *(v2.5.0, #6772/#6774)* each party member carries their own stacks (**All** tab plus a tab per member; **Give**, split/merge, nicknames), and GM inventory changes are applied server-side when the reply is saved, so swipes never double-apply. Game music is context-bound (v2.4.3, #5161): one persistent track per map area and per encounter tier, generated lazily into the Game Assets library; generated SFX and music need an ElevenLabs **Audio** connection with its Game switches on, picked on the wizard's Features step (**Game Audio** card). Setup also has an on-by-default **Quick Time Events** switch (turn it off for screen-reader or untimed play; v2.4.4, #5467).

**Hierarchical Maps** (v2.3; catalog name **World Maps**, id `hierarchical-maps`) — a downloadable Tracker Agent package (see Downloadable Agents (v2.3); guide `docs/agents/hierarchical-maps.md`), enableable in Roleplay and during/after Game creation: a world-map surface plus a full hierarchical map editor (#3691), with its controls nested inside its Chat Settings → Agents entry (#3679). It fully obeys the per-chat Enable Agents toggle. Troubleshooting: incompatible 1.0.x runtimes are quarantined (fixes "t.select is not a function"); inactive-chat Maps calls no longer block sends ("Failed to flush 1 game-state patch callback").

**Scene videos (v2.1)** — a dedicated Video Generation connection (`chat.ts gameVideoConnectionId`/`sceneVideoConnectionId`, selected under Chat Settings → Agents → Scene Videos or the setup wizard) renders MP4s into a scene-video store; they surface in the Gallery **Videos** tab with per-image **Animate** buttons and pinnable/draggable video overlays (also available in Roleplay galleries).

**Storyboards ↺ — now the downloadable Storyboard Agent (Roleplay + Game; not Conversation)**. The v2.1–2.2 Engine-native turn storyboards (Prompt Director, Illustration/Animation Prompt selectors) are gone. Install **Storyboard** from Download Agents (no restart), then per chat turn on **Enable Agents** and **Enable Storyboards** (Chat Settings → Agents → **Storyboards**). **Game:** one finished GM turn → **Keyframes per Turn** images (default 3, 1–6), with separate **Automatic Storyboard Illustrations** / **Animations** switches (clips 5 s, 1–15), in a floating viewer or as the Game background; **Gallery → Create storyboard** on demand. **Roleplay:** completed exchanges become an episode shown inline — **Automatic mode** Manual only / Still images / Animations, plus **Messages per episode**. Prompt chain: **Still Planner** (Still Keyframes) or **Animation Planner** (Comic Page Animation) → **Storyboard Illustration Prompt** (Game Scene Illustration) → **Storyboard Video Prompt** (Cinematic Scene Video). The wizard's **Storyboard Optimized** presentation (Storyboard Game Prompt, `{{gameStoryboardKeyframeCount}}` macro) shapes GM narration only — it does **not** install or activate the Agent. Older Games keep pre-Agent settings as per-chat overrides (reset each to inherit the Agent default). The chat's **Game Video Prompt** now covers only manual Gallery / Game Assets videos; the global video template key is `game.video` (legacy `game.omniVideo` still read). Guide: `docs/game/storyboard.md`; package entry in `references/agents.md`.

**Session History (v2.2)** — an **Initial Game Setup** section exports the complete campaign setup (preferences, prompt choices, visual/storyboard options, safe model descriptors, and effective params, no credentials/local IDs); as of v2.3 the download is a versioned **`.marinara-game-setup.json` bundle** (no longer `.txt`) that refills the New Game wizard on import, remaps local resources, warns about missing ones, and requires a replacement GM connection when necessary (#3701). Per-turn **Peek Prompt** opens the exact cached prompt for a historical GM turn, and completed sessions support **read-only deterministic replay**. The final Game-setup watchdog is 500 seconds (v2.3, #3684).

**Game Illustrator dynamic prompts (v2.1)** — an optional Illustrator toggle (Chat Settings → Agents → Illustrator) for **Dynamic LLM Prompt Generation**: `gameImageDynamicPromptEnabled` (`packages/shared/src/types/chat.ts`) asks the chat/prompt LLM to rewrite Game Mode NPC-portrait, location-background, and key-moment illustration prompts before image gen (optionally via `illustratorPromptConnectionId`). Distinct from the post-processing `illustrator` agent. Related: `gameImageAutoGenerationEnabled`.

## Apps: Noodle and Slurp (downloadable packages — not chat modes) ↺

**Noodle is no longer built in.** It moved into an optional package in v2.4.2 (#4763) and is grouped under **Apps** since v2.5.0 (#6943). Install **Noodle** from **Agents → Download Agents**, restart Marinara Engine when prompted, then open its **Home** tab (address row `marinara/noodle`) — the old top-bar **@** button is gone. Uninstalling removes the Home tab and, after restart, its routes and schedulers, but **keeps Noodle data** for a reinstall. Its routes, scheduler and UI are package-owned now; the base Engine no longer has `routes/noodle.routes.ts`, even though `docs/development/noodle-internals.md` still names it (docs lag code).

What it does is unchanged in substance since v2.2–2.3: a **pretend, fully local Twitter/X-style timeline** where every account belongs to your world — one per **persona** (an in-Noodle switcher changes who you post as), invited **characters**, Professor Mari (a **Professor Mari participates** toggle can keep her out), and optional "random user" accounts. Posts (≤4000 chars) carry an image, polls, likes, reposts, nested replies and `@handle` mentions; characters get AI-written profiles on their first refresh, and public handles are case-insensitively unique across personas and characters, so auto-created ones may come back suffixed (v2.4.0, #4310). **Refresh timeline** has a Generation connection write a batch of posts, replies, likes, follows, polls and missing profiles; **Refreshes/day** (0–24, default 2; 0 = off) schedules it server-side, **Images/refresh** (0–50, default 3) caps generated images, and the **Noodle Prompt** is editable in Noodle Settings (v2.3). Its built-in instructions treat every account as adult (18+), and that is not a setting. **NoodleR**, the paired creator/audience side of the package, adds creator profiles and optional quota-limited synthetic audience activity (v2.4.1–2.4.2).

Two independent bridges to chats: **Carryover to chats** (Noodle settings; separate Conversations / Roleplays / Games toggles, all off by default; adds a "Recent Social Media Activity" block capped at 8,192 tokens) and the per-chat **Allow Noodle references** (off by default; lets a refresh read that chat). Guides: `docs/noodle/overview.md`, `docs/noodle/settings.md`.

**Slurp** (formerly **Slurp Remastered**; **Slurp Legacy** is retired) is the other social App: a private creator platform for your characters and personas — public or locked photos and a simulated audience that follows, subscribes, unlocks, comments and messages, with fictional prices; tuned for adult content by default. Install from Download Agents, restart, open **Home → Slurp**. A chat's characters remember their Slurp activity only with **Include Slurp activity** (Chat Settings → Connected Chats, off by default) *and* carryover on for that mode in Slurp's settings (v2.4.6, #6235). Noodle and Slurp chat controls, and the lorebook Noodle/Slurp generation filters, appear only while their package is installed; their image-canvas settings live in each package's own settings. Since Capability API 1.66 a package can start a Roleplay scene from its own thread (e.g. a Slurp DM; **Back** returns to it; #7118). Package guide: `packages/slurp2/README.md` in Pasta-Devs/Marinara-Agents.

## Multiplayer Rooms (optional, work in progress — v2.5.0, #6790)

Private rooms for **Conversation, Roleplay and shared Game rounds**, with no fixed human or AI roster cap. **Off by default behind two gates:** `MULTIPLAYER_ENABLED=true` in the `.env` of **every** participating Engine (exact value `true`, restart required), then **Settings → Advanced → Multiplayer** (section labelled **Multiplayer WIP**) to enable the separate setting. The host starts a room from the normal setup flow (**Create shared session** / **Play together**); hosting needs `SSL_CERT`/`SSL_KEY` valid for the room hostname, a separate HTTPS room port routed through the firewall (never the ordinary Engine API), and a room password of at least 12 characters. Each guest uses **their own** trusted Marinara install (no AI connection needed), reviews the invitation (expires after 30 minutes) and requests admission; the host approves each player in **Players**, controls generation (allowance of 100 coordinated turns per hosting session by default; Pause/Resume/Stop) and **provides the AI connections — and can read and retain everything shared**. Rooms carry bounded text only: no file or media transfer; custom/package tools, Game Experiences and media are unavailable; the Android native wrapper can't join. In Game, every human submits an action or passes before the GM resolves the round. Guides: `docs/CONFIGURATION.md` → Optional multiplayer; contributor trust boundary in `docs/development/multiplayer.md` (peers and model output stay untrusted after password auth).

## Prompt Assembly (Simplified)

For a roleplay turn, the system prompt is assembled roughly as:

1. **Preset sections** (ordered, user-configurable) — typically:
   - System role / jailbreak
   - Character description + personality + scenario — as of v2.3.4 (#3817) character/persona sections keep a guaranteed editor order across preset markers, fallbacks, agent lore, and Game/scene card contexts: Description, Personality, Backstory, Appearance, Scenario, then Example Dialogue when present
   - Persona description
   - World info / lorebook entries (injected based on keyword matches in recent messages)
   - Examples of dialogue
   - Chat summary (if enabled and conversation is long)
   - Connected-chat awareness (if this chat is linked to another)
   - Agent injections (from pre-generation agents)
2. **Recent message history** — the chat's last N messages
3. **Depth-injected prompts** — special prompts inserted at specific depths in the history
4. **Post-history instructions** — note (v2.0): post-history *system* sections are now injected as **user-side** content at a configured depth (preserving metadata) rather than glued onto the pre-history system prompt

**v2.0–v2.1 prompt-assembly changes:** max-context enforcement keeps non-history material first and *then* windows recent history (preserving response headroom); assistant **prefill steering** seeds the reply; **visible tracker context** is included; 1:1 Conversation assistant turns are **speaker-labeled with the character name**; fallback-preset impersonation drops conflicting non-marker sections (#3209) and Smart order no longer overrides `/guided` or `/impersonate` (#3212); text attachments are bounded by the context window rather than pre-truncated at 60,000 chars.

**v2.3.4: prompt leaf content is verbatim.** Card fields, persona, lorebook entries, memories, and scene text are no longer HTML-escaped — angle-bracket markup (`<thinking>`, `<scenario>`, inline `<div>`) reaches the model exactly as written (local single-user threat model; supersedes #3108's escaping). Structural section wrappers and agent value/attribute escapers are unchanged. *(v2.5.0)* Multiplayer rooms change that trust boundary — room policy is enforced at rendering, storage, command and tool dispatch, with peer traffic on a separate restricted listener (`docs/development/multiplayer.md`).

**v2.4.x–v2.5.0 prompt-assembly changes:** up to ten **pinned messages** stay in the prompt past the history window (see The Chat Surface). **Decision statements** (`{{#if decision:"…"}}`) in presets, cards, lorebooks and agent prompts are answered once per turn by the Decision model, capped by **Decision statements per turn** (32 default, up to 255); keep decision blocks low in a preset, because a changing answer near the top makes caching providers re-bill the whole prompt (`references/conditional-prompts.md`). Advanced Memory Recall adds the `recalled_scenes` marker. With several lorebook markers, each world-info position is filled by the first marker covering it, so entries no longer duplicate (v2.4.6, #5716). Example dialogue falls back into the Character Info marker when a preset has no Dialogue Examples marker, while a *disabled* one still omits it (v2.4.3). When a prompt doesn't fit, generation spends the reply budget instead of dropping messages and logs a warning at the 128-token floor (v2.5.0, #6614). Generation parameters gained an **Assistant Reasoning Prefill** for compatible OpenAI-style endpoints (v2.4.3) and an Advanced Parameters history format of Apply / Don't Apply / **Single User Message** (v2.4.6, #5915).

For conversation mode, assembly is simpler: system prompt (mode-specific framing + character card) + name lists + fetched context + message history.

**v2.3 Conversation-assembly changes:** Peek Prompt groups Conversation turns under a "Chat History" section; join/leave notices become timestamped history events only after chat start; reaction syntax lives in "Commands"; merged-group speaker-prefix and character-only response boundaries emit last in the preset's XML/Markdown/plain format; and identity wording fits both 1:1 and group chats (with a startup preset migration).

The assembly lives in `packages/server/src/routes/generate.routes.ts` and `packages/server/src/routes/generate/` helpers. For contribution work, note that generation logic has been factored into focused modules (prompt, provider, context, and command-runtime concerns — separating Conversation commands, Professor Mari actions, turn games, provider setup, and post-processing) rather than a single monolithic route file. Arbitrary user code **can't hook it without forking** — but reviewed capability packages holding the `prompt-context` permission contribute text to each turn's system prompt (v2.4.1, #4526), and Roleplay tracker packages place prompt blocks through preset Agent sections (v2.4.4, #5408).

## Data Storage

**File-native JSON storage throughout** (as of v2.3.0), under `DATA_DIR/storage` (default `packages/server/data/storage`). v2.3.0 removed the retired database compatibility stack (runtime backend switch, startup migrations, importer/repair readers, migration scripts, DB-file backup handling, external ORM deps). The file store enforces primary/natural-key constraints; graceful-shutdown flush was hardened (#3602), native profile imports are atomic (#3683), and packages resolve capability-owned schemas by registered name (#3647). Since v2.4.2–2.4.4 every table is **sharded by owner** (one chat's messages, one lorebook's entries, …) instead of rewriting a global JSON file per save; chats load lazily on first open (v2.4.5; `MARINARA_EAGER_STORAGE=1` restores load-everything startup), and `MARINARA_MAX_RESIDENT_CHATS` caps how many stay in memory (unlimited by default, `8` on Termux and SteamOS; evicted chats stay on disk). The storage format is at **version 7** (`STORAGE_VERSION`, `storage-format.json`), and a **downgrade guard** blocks launching or updating onto an older build that can't read it — users can't simply roll back; the offline `unshard` command in `scripts/protect-launcher-data.mjs` is the escape hatch (`docs/development/file-storage.md`). `storage/` holds the text tables (real names; full set in `packages/server/src/db/schema/`):
- `chats`, `messages`, `message_swipes`, `message_trash` (v2.5.0 Trash), `chat_folders`, `chat_presets` (**settings profiles** — legacy name)
- `characters`, `personas`, `character_groups`, `persona_groups`, card version history
- `lorebooks`, `lorebook_entries`, `lorebook_entry_activation_stats`
- `prompt_presets`, `prompt_sections`, `prompt_groups`, `choice_blocks`, `regex_scripts`
- `api_connections` (API keys encrypted with `DATA_DIR/.encryption-key`, AES-256-GCM, unless `ENCRYPTION_KEY` is set)
- `agent_configs` (built-in configs and custom agents), `agent_runs`, `memory_chunks`, `advanced_memory_records`, `conversation_notes`, `mari_instructions`
- `custom_tools`, `game_rulesets`, game state/checkpoint tables
- `custom_themes` and `installed_extensions` (**Personal Extensions returned in v2.3.5** — records carry the approved SHA-256 hash, enabled flag, declared capabilities, and revision history; anything from *before* the 2.3.4 purge is gone for good and is not restored by 2.3.5)
- **Media lives beside `storage/`, not in it** — sibling `DATA_DIR` folders `avatars`, `sprites`, `backgrounds`, `gallery` (generated/uploaded images **and videos**; v2.1 renamed "clips" → **Videos** and split galleries into Images/Videos tabs, newest-first), `fonts`, `knowledge-sources`, `game-assets`, `custom-emojis`, `custom-stickers`; packages in `capability-packages` (`docs/data/where-data-is-stored.md`).

Fully local. For backups point users at **Download Backup** and the rotating daily/weekly/monthly **automatic backups** (v2.4.0; last run and failure state shown) under **Settings → Advanced → Backup & Export** (`docs/data/backup-and-restore.md`) first; profile and backup ZIP exports stream to disk in bounded JSONL shards (no more `Invalid string length`), and profile imports preview first and quarantine executable tools, Personal Extensions, persistent Mari memories and active themes for deliberate re-enabling (v2.4.2). The manual fallback is copying the **whole `DATA_DIR`**, including `.encryption-key` and the media and package folders — copying `storage/` alone loses media and leaves saved API keys undecryptable. A backup ZIP holds the key file, so keep it private. **Export Profile** strips API keys and webhook URLs, and **Import Profile (JSON/ZIP)** (Settings → **Imports** → Profile & Marinara) restores from the profile copy even inside a backup ZIP — re-enter keys and webhook URLs afterwards. Sharing = exporting individual objects as JSON (characters, presets, lorebooks all have export endpoints); chats can also export as readable Markdown/HTML transcripts (v2.5.0).

### Localization — two separate settings, don't conflate them (v2.3.5 / v2.4.0)

Marinara has **two independent language controls**, and confusing them is an easy support mistake:

**1. Interface language** (*v2.3.5*) — **Settings → General → App Behavior → Language**. Localizes application UI text only: controls, labels, guidance. It does **not** touch model prompts, authored content, or chat messages. English (`en.json`) is canonical, bundled, and the runtime fallback, so a missing translation shows English rather than a key or an empty control. **↺ Community UI translations download on demand** (v2.4.6, #5827): selecting a language fetches `ui/<locale>.json` from the `docs-i18n` branch into `DATA_DIR/ui-packs` (works offline afterwards; **Refresh language pack** updates it; never downloaded automatically). Existing non-English users had to reselect their language once after that upgrade. The selection also propagates into downloadable Agent interfaces.

Twelve locales: Arabic (**right-to-left**), Simplified Chinese, English, French, German, Hindi, Japanese, Korean, Polish, Brazilian Portuguese, Russian, Spanish. *(v2.4.0)* Native language names in the dropdown are capitalized (Español, Français, Polski, Português (Brasil), Русский).

**2. Documentation Language** (*v2.4.0*) — **Settings → General → Documentation Language**, also offered at the end of the first-time tutorial. Controls the language of the **in-app guides**, which ship as **downloadable packs** from the repo's `docs-i18n` branch.

- **Download & Replace** fetches the selected language (integrity-checked) and **removes the previous pack** — installs carry exactly one language. Untranslated guides open in English with an **`EN` badge**; docs search works in the active language.
- The choice survives updates (the pack auto-refreshes when its translations changed); a **Fix documentation** failsafe re-downloads or resets a broken pack.
- **Ten documentation languages at v2.5.0**: Spanish, German, French, Brazilian Portuguese, Polish, Russian, Japanese, Korean, Simplified Chinese, and **Hindi** (v2.4.1, #4471) — each covering the full guide set (~136 English guides at v2.5.0, developer docs included; `packages/shared/src/constants/docs-languages.ts`). Translator settings can be saved as defaults for new chats (v2.4.6), and automatic output translation finishes and saves server-side even after the page closes (v2.5.0, #6412). `docs/integrations/message-translation.md`.

## What's NOT Built-In

Important for recommendations:
- No external vector-DB integration (Pinecone, Weaviate, …). Vectors live in Marinara's own file store; embeddings come from a connection's embedding model or the built-in local MiniLM fallback.
- No *unrestricted* client extension mechanism. The old full-trust CSS/JS feature was removed in v2.3.4; **v2.3.5 reintroduced sandboxed Personal Extensions** (see `references/extensions.md`). What's genuinely absent is ambient authority: a sandboxed extension cannot reach messages, presets, lorebooks, undeclared card fields, chat metadata, the DOM, the database, or the network. Those need a broker capability in the engine, the un-sandboxed Full page access path (External Extensions, double-gated), or a fork. Server Extensions are unavailable on Windows and Android.
- No third-party plugin marketplace — official capability packages install from the in-app **Download Agents** catalog (v2.3; update-on-confirm, per-major lanes); as of v2.3.4, disabled-by-default **custom GitHub agent repositories** (#3861) add an opt-in third-party install path.
- No hooks into the prompt assembly pipeline for arbitrary user code — you can't insert your own logic mid-generation without forking. *Qualified (v2.4.1+):* a reviewed capability package holding the `prompt-context` permission can contribute text to each turn's system prompt, and tracker packages can place prompt blocks via preset Agent sections — that packaging path is the only non-fork route.
- No multi-user accounts — it's single-user / local-first by design. *Qualified (v2.5.0):* optional **Multiplayer rooms** (see above) let guests on their **own** Marinara installs join a host's Conversation, Roleplay or Game room, but that's peer rooms with the host's AI connections, not shared logins on one server. Multiple users on one install still need a proxy + auth layer you build.
- Script tools (off by default; `CUSTOM_TOOL_SCRIPT_ENABLED=true`) have no network, no filesystem, no `require`. Pure JS computation only.
- No built-in way to add new **chat modes** — the mode enum is fixed at three. *Qualified:* a capability package can supply a whole **Game Experience** via the `game-surface` slot (chosen in the New Game wizard), Apps such as Noodle and Slurp add Home tabs, and a **ruleset** JSON file changes Game Mode's mechanics — none of these adds a mode.
- No native GraphQL, no tRPC, no realtime subscriptions beyond SSE for generation.

If the user needs any of these, the answer is usually "webhook tool to your own backend" or "fork the engine."
